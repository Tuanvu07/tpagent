# Core design decisions (agent A)

- **Internal message format** is provider-neutral dicts (`user` / `assistant`+`tool_calls` / `tool`). Tool results carry `image_png` bytes; Anthropic gets base64 image blocks inside `tool_result`, OpenAI-compatible APIs get a follow-up `user` message with an `image_url` data URI (the `tool` role cannot hold images there).
- **Provider inference from model name**: `claude-*` -> anthropic, `deepseek-*` -> deepseek, `qwen/*` -> openrouter, `qwen*` -> qwen (DashScope), `gemini-*` -> gemini, `gpt*` -> openai. Explicit `provider:model` (e.g. `ollama:qwen3:8b`) always wins. `TPAGENT_PROVIDER=fake` forces every tier to the fake provider so the CLI runs with no keys.
- **Routing** is heuristic only (keywords, number of file paths mentioned, length). `classify_with_llm` exists for optional use but the agent does not call it by default, to keep zero-cost routing.
- **Pricing**: Haiku 5.5 long-prompt tier (>100k input) is applied per call. Cached input tokens are billed at 10%. Unknown models count as $0 and are flagged in `/cost`. Sonnet 5.5 and gpt-5-mini prices are placeholders marked "(~approx)".
- **Context**: three layers - per-result truncation (30k chars), shrinking old tool outputs to 2k chars (dropping old screenshots), then LLM summary of everything except the task and the last 6 assistant turns. Hard cap is `min(config, 90k)` tokens so prompts stay under Haiku's 100k boundary. tiktoken loads in a background thread (it downloads its BPE file on first use); until it is ready, or offline, `len/4` is used.
- **Permissions**: only `dangerous=True` tools prompt. For `bash`, with `safe_commands_auto` on, only commands matching `is_destructive()` prompt. Answer `a` remembers "always allow this tool" for the session. Without a TTY and without `--yes`, dangerous calls are denied and the model is told not to retry.
- **Parallel tools**: calls in the same turn run concurrently only when every tool is tagged `read` and not dangerous; otherwise sequentially in order. Results are always appended in call order.
- **Sessions** are persisted to `~/.tpagent/sessions/<id>.json` after each run; images are replaced with their byte count.
- **Path guard**: file tools refuse paths outside cwd unless `allow_outside_cwd: true`. `bash` is unrestricted by path (it is the dangerous tool).
- **CLI**: Typer single-command app; `main()` is the console-script entry and `python -m tpagent` works via `__main__.py`. Intermediate assistant text is printed as it arrives; the final answer is shown once in a panel.
- **Tests** never touch the network. tiktoken is not required for the suite to pass.

# Core upgrade (agent A, round 2): hooks, streaming, thinking, memory/tasks/skills

- **Async permissions**: `PermissionManager(auto_approve, safe_commands_auto, interactive=None, approver=None)`. The agent calls `check_async`: auto_approve/allow-list -> `await approver(tool, args)` -> TTY prompt via `asyncio.to_thread` -> deny. Every denial (including an approver "no") is logged to `denied_log`. `check()` stays for sync embedders and never calls the approver.
- **Agent hooks**: `Agent(approver=..., ask_user=..., workspace=..., thinking=..., max_turns=...)`. `approver` is only used to build the default `PermissionManager`; pass `permissions=` to override entirely. `ask_user` is published to tools through the `tpagent.tools.ask_user.CURRENT_ASK` contextvar for the duration of `run()` (same pattern as the subagent depth guard); subagents inherit it. Without a hook the `ask_user` tool returns "No user available; decide yourself and state the assumption." so the loop never blocks.
- **Workspace root**: `tpagent/tools/workspace.py` holds it. Resolution order: `CURRENT_WORKSPACE` contextvar (pinned by `Agent.run` to `agent.workspace`, so several web sessions with different workspaces run safely in one process) -> process-wide `set_workspace()` (called by `make_default_agent(workspace=...)`) -> cwd. `files.resolve` guards against this root instead of cwd; `bash` runs with `cwd=workspace` unless the model passes `cwd`. State (`tasks.json`, `MEMORY.md`) lives in `<workspace>/.tpagent/`.
- **Streaming**: providers declare `supports_streaming`; the agent then passes `stream=True, on_delta, on_thinking` and emits `text_delta` / `thinking_delta` events. The `text` event (intermediate text of a turn that also called tools) is still emitted with `streamed: true|false` so UIs that render deltas can skip it. The final answer arrives in `done` as before. Anthropic uses `messages.stream` and the SDK's synthesized `text`/`thinking` events; OpenAI-compatible streaming folds `delta.tool_calls` fragments by `index` and reads usage from the last chunk (`stream_options.include_usage`). The fake provider streams word by word so the CLI/web UI can be demoed offline.
- **Extended thinking** (Anthropic only): config `thinking: {cheap: 0, standard: 0, strong: 4000}` -> budget per tier; `Agent.thinking` = None (per config) / True (force; falls back to 4000 when the tier has 0) / False (off). `max_tokens` is raised to `budget + 2000` when needed. Thinking and redacted-thinking blocks are stored verbatim (with `signature`) on the assistant message under `"thinking"` and replayed first in the next request; they are also persisted in the session JSON. Explicit `--model` has no tier, so thinking is off unless forced. OpenAI providers ignore the budget.
- **Core tool modules** (always loaded): `tasks` (in-memory per process, mirrored to `.tpagent/tasks.json`, reloaded when the workspace changes), `memory` (`.tpagent/MEMORY.md`, 8k-char cap enforced on write/append), `skills` (`<workspace>/skills/*/SKILL.md` > `~/.tpagent/skills` > bundled `<repo>/skills`, de-duplicated by name; the prompt lists `name: description` and `use_skill` returns the body), `ask_user`. Only `task_list`, `memory_read`, `use_skill` carry the `read` tag (parallel-safe).
- **System prompt** is built in `core/prompt.py`: base (default or `system_prompt=`) + `## Skills` (only when the `use_skill` tool is present) + `## Memory` (only when the file has content). It is rebuilt every turn so memory written mid-task is visible on the next call.
- **Sessions** moved to `core/sessions.py`: `load_messages(config, id)` drops images (a "[image omitted on resume]" note is appended to the text), `list_sessions(config)` newest first; `Agent.load_session(id)` swaps the conversation in place and keeps the id so the file is updated, not forked. CLI: `--resume <id>`, `/sessions`, `/resume <id>`.
- **make_default_agent** also accepts `tools=`, `system_prompt=`, `max_turns=` (what `subagent.py` offers) and treats a tier name passed as `model` as a tier, so children get thinking/routing per tier. It sets `subagent.CONFIG` so children share the parent's config.
- **CLI** prints `text_delta` live and skips the final panel when the answer was already streamed; `thinking_delta` is shown dim/italic. `/think on|off|auto`, `--think/--no-think`, `--workspace`. `ask_user` on the TTY accepts an option number or free text.
